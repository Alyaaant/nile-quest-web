# NILE QUEST — 面接提出前のチェックリスト

対象：**面接専用のNILE QUESTのみ**。既存のSkolivio・そのGitHub・Railway環境・DBは触らない。

## 1. ローカルでの確認

```bash
node -v    # Node.js 22.13以降
npm run check
npm test
npm start
```

ブラウザで `http://localhost:3000` を開き、「新規登録 → Egypt開始 → 3問回答 → Istanbul解放 → PASSPORT → RANKING → ログアウト → 再ログイン」を確認する。

## 2. GitHub（**新しい**公開リポジトリ）

Macで `gh auth login` を済ませた後、プロジェクト直下から `bash scripts/publish-github.sh` を実行。ユーザー名 `Alyaaant` を検証し、既存のリポジトリがあれば処理を停止する。**Skolivioにはコミットしない。**

共有するコードURLは、GitHub作成後に表示されるもの。GitHubのURLは遊べるWebサイトのURLではない。

## 3. デプロイ（新規で独立した環境を使う）

- Node.js 22以上で `npm start` を実行できるホスティングを用意する。
- 永続ディスクに `/data` をマウントし `DATA_DIR=/data` を設定する。ディスク無しのホスティングでは**再起動時にユーザーデータが消える可能性がある**。
- `NODE_ENV=production`、`DEMO_EMAIL`、`DEMO_PASSWORD`（12文字以上、専用の強力なランダム値）、`DEMO_NAME` を**ホスト側のシークレット設定**に登録する。
- 実サービスでHTTPSの公開URLを用意する。会社に送るのはその公開URL。
- `DEMO_PASSWORD` を変更した場合はアプリを再起動して新しい値を反映する（旧セッションも無効化）。
- サービス利用によって料金が発生する可能性がある。新規ホスティング契約・有料ディスクの確認はユーザー自身が行う。

## 4. 公開後の動作確認

```bash
TEST_URL=https://your-domain.example \
DEMO_EMAIL=reviewer@example.com \
DEMO_PASSWORD='your-private-demo-password' \
npm run verify:live
```

このコマンドは面接用のデモアカウントにEgyptの1プレイ記録を追加する。**Skolivioには一切アクセスしない。**

その後、PCとスマホのシークレットモードで以下を確認する。

- [ ] パスワード入力とログインが成功する
- [ ] Egyptの問題に回答できる
- [ ] 2問正解で次の国が開放される
- [ ] PASSPORTとRANKINGが更新される
- [ ] 再ログインしても記録が残る
- [ ] 現地天気を表示できる（外部サービス障害時は代替メッセージを確認）
- [ ] GitHubの公開リポジトリに `.env`、DB、実在する学校データ、パスワードが含まれていない
